# Security review, November 2026

Scope: RepakHub v0.6.0 (`main` at `7b4fd4a`): the Rust core (`apps/desktop/src-tauri/src`), the React UI, Tauri configuration and capabilities, the update and download engine, the demo source, dependencies, and the GitHub Actions workflows. Method: code review of every module against the threats below, automated checks (`cargo audit`, `pnpm audit`, searches for unsafe code, raw HTML, string-built SQL and committed secrets), and a headless-browser check of the new Content Security Policy. Not in scope: testing on real Windows and Linux machines with games installed (M6), and code signing (M7).

## Threat model

| Who | Wants to | Through |
| --- | --- | --- |
| Someone who controls a file RepakHub reads (a planted launcher manifest, a USB drive in a scan location) | Read or write outside the game folder, leak Windows credentials, crash the app | Launcher metadata, install records, executables |
| A malicious or compromised download server, or someone on the network | Get unverified files installed, especially executables | Update manifests, downloads, redirects |
| Content shown in the UI (store data, game names) | Run script in the webview, which can call RepakHub's commands | Rendered text, image and link URLs |
| Another user on the same machine | Read the Steam API key, library or save backups | The app data folder |
| A compromised build dependency or GitHub Action | Tamper with releases | CI and release workflows |

## Findings

| # | Finding | Severity | Status |
| --- | --- | --- | --- |
| 1 | No Content Security Policy (`"csp": null`). Any script injected into the webview could call every allowed command and load anything | High | **Fixed**: strict CSP (scripts and styles from the app only; images from the app, Steam's CDN and GOG's image host only; connections only to Tauri's IPC; no plugins, framing, base or form targets). A separate, looser `devCsp` is used only by the development server. Verified: the built UI renders under the policy with no violations in headless Chrome, and a control with scripts blocked fails as expected |
| 2 | App data folder and database world-readable (`755` / `644`). On Linux (`~/.local/share`) other local users could read the Steam API key, the library and save backups. macOS is protected by the private `~/Library` | Medium | **Fixed**: folder `700`, database `600` on Unix; SQLite gives its side files the same mode. Tested |
| 3 | CI workflow had no `permissions` block and used movable action tags. The repository default token is read-only, so no write access was exposed, but a settings change would have widened it | Low | **Fixed**: explicit `contents: read`, `persist-credentials: false`, every action pinned to a commit SHA (as `release.yml` already was) |
| 4 | Steam API key stored in plain text in the settings database rather than the OS keychain | Low | **Accepted for now**: mitigated by #2 and by the key never appearing in errors or the UI (password field; `owned.rs` reduces every error to a message without the URL). Recommendation: move to the OS keychain before v1.0 |
| 5 | Transitive dependencies flagged by `cargo audit`: unmaintained `proc-macro-error`, `zbus_names`, `zvariant`, `zvariant_derive`, `chrono` (lockfile only, not built for our targets); unsound `glib` 0.18 (`VariantStrIter`, an API RepakHub does not use) | Informational | **Accepted**: all come from Tauri's Linux GTK3 stack or the D-Bus library behind `tauri-plugin-opener` and `tauri-plugin-single-instance`, with no fixed versions available. Track Tauri releases; re-run `cargo audit` before each release |

No known vulnerabilities in any dependency (`cargo audit`, `pnpm audit`).

## Controls verified

**Untrusted local files** (launcher metadata, install records, executables)
- Sizes capped (4 MB metadata, 32 MB executable resources, 1 MB manifests, 64 KB catalog index); VDF nesting capped at 32.
- Paths from metadata are never network (UNC) paths in any separator spelling; on Windows, symlinks and junctions to launcher files are not followed.
- Relative paths from launchers (Steam `installdir`, executable paths, install-record file lists) must be plain relative: no root, drive, `..` or `.`.
- The executable version reader bounds-checks every offset and reads only headers and the resource section.
- Hidden and system folders are not searched; scans go two folders deep, never across a whole drive.

**Updates and downloads**
- Manifests are accepted only with an Ed25519 signature (`verify_strict`) from a key compiled into the app; the only registered key is the demo source's, its private half kept off the repository.
- After the signature check: schema, source, unknown fields, paths (relative, portable, unique ignoring case), lowercase SHA-256, HTTPS URLs on hosts the manifest lists, no port or credentials.
- Every request hop, including redirects, is checked against the listed hosts; resume is trusted only when `Content-Range` matches; downloads stop at the declared size; every file is SHA-256 verified before it leaves staging.
- Executables are refused unless the key belongs to the rights holder: by name in the manifest and by content (MZ, ELF, Mach-O, `#!`) after download.
- Apply is all or nothing with backup and rollback, and refuses a folder that holds another game.

**Webview and commands**
- No raw HTML rendering anywhere; React escapes all text. Store results pass only `https://www.gog.com/` links and `https://images.gog-statics.com/` images.
- URL opening is restricted by capability to the launcher schemes (`steam://`, `goggalaxy://`, `com.epicgames.launcher://`), `https://www.gog.com/` pages and the single Steam API key page; launcher URLs URL-encode ids read from disk.
- No string-built SQL; every query is parameterised. No `unsafe` Rust.

**Local data**
- Save backups never follow symlinks, cannot include RepakHub's own backup folder or a whole drive, validate ids before delete or restore, and take an automatic backup before restoring.
- One app instance at a time, so two processes never write the same database.

**Releases**
- Release builds run read-only with no token; only the `publish` job can write, and it runs no project code. Tags must be on `main` and match the app version. Actions pinned.

## Recommendations before v1.0

1. Code-sign Windows and macOS builds (also removes the SmartScreen and Gatekeeper warnings).
2. Move the Steam API key to the OS keychain (finding 4).
3. Re-run this review when third-party adapters are built (ADR 0001), focusing on the WebAssembly host functions.
4. Run `cargo audit` and `pnpm audit` in CI so new advisories fail the build.
